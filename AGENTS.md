# Project instructions

## Code discovery

This project uses codebase-memory-mcp. Prefer `search_graph` to find symbols, `trace_path` for callers and data flow, and `get_code_snippet` to read a located symbol. Use `query_graph` for complex relationships and `get_architecture` for an overview. Run `index_repository` first if this repository is not indexed. Use `rg` for string literals, configuration, non-code files, or when the graph is insufficient.

## Project layout

- `backend/app.py`: FastAPI health and classification endpoints using the local Laya model.
- `backend/fetch_real_products.py`: refreshes the selected product catalog and local images.
- `backend/validate_products.py`: checks catalog, frontend data, and local image consistency.
- `frontend/src/data/products.ts`: product data used by the UI; generated by the refresh script.
- `frontend/src/data/products_manifest.json`: source URLs and image hashes; also preserves the selected product IDs for refreshes.
- `frontend/public/products/`: the 50 local product images.
- `frontend/AGENTS.md`: additional Next.js instructions for frontend work.

## Product data rules

- Keep the existing 50 product IDs unless the user requests a different selection.
- Take each product's name, category, description, and image URL from the same official Cotopaxi or Tentree catalog record. Keep source text as published; do not invent or infer missing specifications.
- Refresh data with `python -m backend.fetch_real_products` from the repository root. This updates the images, manifest, and `products.ts` together. Do not edit generated product records by hand.
- After a refresh, run `python -m backend.validate_products` and inspect `/preview` for image and title alignment.

## Checks

- Python unit tests: `python -m unittest backend.test_product_catalog -v`.
- Frontend: run `npm run build` and `npm run lint` from `frontend/`. Report existing lint failures separately from failures caused by a change.
- The Python virtual environment is at the repository root in `.venv/`; frontend dependencies are in `frontend/node_modules/`.
